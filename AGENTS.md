# AGENTS.md

This file provides guidance to AI coding assistants working with code in this repository.

## Development Commands

**Prerequisites (Apple Silicon Mac, macOS 14+):**

- [Rust](https://rustup.rs/) (latest stable)
- [Bun](https://bun.sh/) package manager
- CMake, and Xcode or its command-line tools

**Core Development:**

```bash
# Install dependencies
bun install --frozen-lockfile

# Install the speech model and the VAD resource (see "Models" below)
scripts/setup-models.sh

# Run in development mode
CMAKE_POLICY_VERSION_MINIMUM=3.5 bun run tauri dev

# Build the app bundle
CMAKE_POLICY_VERSION_MINIMUM=3.5 bun run tauri build

# Frontend only development
bun run dev        # Start Vite dev server
bun run build      # Build frontend (TypeScript + Vite)
```

**Checks (run before committing):**

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib
bun run lint              # ESLint for frontend
bun run lint:fix          # ESLint with auto-fix
bun run format            # Prettier + cargo fmt
bun run format:check      # Check formatting without changes
./eval/run.sh             # Refine eval against the configured endpoint
```

## Models

The app never downloads models. `scripts/setup-models.sh` installs them outside the app, downloading each file from its original publisher at a pinned revision and checking its SHA-256:

- Silero VAD v4 from the Silero project on GitHub, into `src-tauri/resources/models/` (build-time resource).
- NVIDIA Parakeet TDT 0.6B v3 (int8 ONNX conversion) from Hugging Face, into `~/Library/Application Support/dev.hushtype.app/models/`.

The model manager (`managers/model.rs`) only resolves models already on disk: the built-in folder names, custom `.bin`/`.gguf` files in the models directory, and GGUF models in the shared Hugging Face cache.

## Architecture Overview

hushtype is a macOS dictation app built with Tauri 2.x (Rust backend + React/TypeScript frontend). Hold a shortcut, speak, release, and cleaned text is pasted at the cursor. Speech recognition runs locally; cleanup optionally goes to one OpenAI-compatible endpoint the user configures.

### Backend Structure (src-tauri/src/)

- `lib.rs` - Main entry point, Tauri setup, manager initialization
- `managers/` - Core business logic:
  - `audio.rs` - Audio recording and device management
  - `model.rs` - Local model registry and on-disk resolution
  - `transcription.rs` - Speech-to-text processing pipeline
  - `history.rs` - Transcription history storage
- `audio_toolkit/` - Low-level audio processing:
  - `audio/` - Device enumeration, recording, resampling
  - `vad/` - Voice Activity Detection (Silero VAD on ONNX Runtime)
- `refine.rs` - Transcript cleanup through the configured endpoint, with raw fallback
- `modes.rs`, `context.rs`, `context_macos.rs` - Per-app modes and the context they may send
- `paste_tx/` - Receipt-sequenced clipboard paste
- `commands/` - Tauri command handlers for frontend communication
- `cli.rs` - CLI argument definitions (clap derive)
- `shortcut/` - Global keyboard shortcuts (`native_keys.rs` and `tauri_impl.rs` backends)
- `secure_input.rs` - macOS Secure Input detection and fallback
- `settings.rs` - Application settings management
- `overlay.rs` - Recording overlay window
- `tray.rs` - Menu bar icon and menu
- `signal_handle.rs` - `send_transcription_input()` reusable function

### Frontend Structure (src/)

- `App.tsx` - Main component with onboarding flow
- `components/` - React UI components:
  - `settings/` - Settings UI
  - `model-selector/` - Model management interface
  - `onboarding/` - First-run experience
  - `overlay/` - Recording overlay UI
  - `shared/`, `ui/`, `icons/`, `footer/` - Shared components
- `hooks/useSettings.ts` - Settings state management hook
- `stores/settingsStore.ts` - Zustand store for settings
- `bindings.ts` - Auto-generated Tauri type bindings (via tauri-specta, regenerated by debug builds)
- `overlay/` - Recording overlay window entry point

### Key Architecture Patterns

**Manager Pattern:** Core functionality organized into managers (Audio, Model, Transcription) initialized at startup and managed via Tauri state.

**Command-Event Architecture:** Frontend → Backend via Tauri commands; Backend → Frontend via events.

**Pipeline Processing:** Audio → VAD → Parakeet/Whisper → Refine (optional) → Dictionary replacements → Paste

**State Flow:** Zustand → Tauri Command → Rust State → Persistence (tauri-plugin-store)

### Application Flow

1. **Initialization:** App starts in the menu bar, loads settings, initializes managers
2. **Setup:** Onboarding checks Microphone and Accessibility permissions and asks for an installed model
3. **Recording:** Global shortcut triggers audio recording with VAD filtering
4. **Processing:** Audio is transcribed locally, then optionally refined by the configured endpoint
5. **Output:** Text is pasted into the focused app; the clipboard keeps it if paste cannot be confirmed

## Internationalization (i18n)

All user-facing strings must use i18next translations. ESLint enforces this (no hardcoded strings in JSX).

1. Add the key to `src/i18n/locales/en/translation.json`
2. Use it in a component: `const { t } = useTranslation(); t('key.path')`

## Code Style

**Rust:**

- Run `cargo fmt` and `cargo clippy` before committing
- Handle errors explicitly (avoid unwrap in production)
- Use descriptive names, add doc comments for public APIs

**TypeScript/React:**

- Strict TypeScript, avoid `any` types
- Functional components with hooks
- Tailwind CSS for styling
- Path aliases: `@/` → `./src/`

## CLI Parameters

**Implementation:** `cli.rs` (definitions), `main.rs` (parsing), `lib.rs` (applying), `signal_handle.rs` (shared logic)

| Flag                     | Description                                                |
| ------------------------ | ---------------------------------------------------------- |
| `--toggle-transcription` | Toggle recording on/off on a running instance              |
| `--toggle-post-process`  | Toggle recording with post-processing on/off               |
| `--cancel`               | Cancel the current operation on a running instance         |
| `--start-hidden`         | Launch without showing the main window (tray icon visible) |
| `--no-tray`              | Launch without system tray (closing window quits the app)  |
| `--debug`                | Enable debug mode with verbose (Trace) logging             |
| `--transcribe-file WAV`  | Transcribe a file headlessly and exit                      |
| `--list-models`          | List known models and whether they are installed           |

CLI flags are runtime-only overrides and do not modify persisted settings. Remote-control flags work via `tauri_plugin_single_instance`: a second instance sends its args to the running one, then exits.

## Debug Mode

Access debug features with `Cmd+Shift+D`.

## Platform Notes

- **macOS** is the supported platform: Apple Silicon, macOS 14+, Metal acceleration. Accessibility permission is required for shortcuts and paste. Ad-hoc rebuilds can leave a stale Accessibility grant; see "Permission recovery" in the README.
- Windows and Linux code paths remain from the original engine and are kept compiling, but are not built or tested. Their environment overrides are `HUSHTYPE_KEEP_VULKAN_IMPLICIT_LAYERS` (Windows) and `HUSHTYPE_NO_GTK_LAYER_SHELL` (Linux).
